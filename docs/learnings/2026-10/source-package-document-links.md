# 源码包的文档也需要完整交付

## 为什么文件齐全仍会失链

打包测试检查 README、内核和锁文件存在，并不能证明 README 引用的验收文档也存在。若把初始化模板的精简规则直接用于源码交付，计划和验收记录可能被排除，但入口文档仍指向它们。

初始化关注新项目的起始状态，可以省略旧任务记录；源码包描述当前项目，需要保留公开文档引用的依据。两者可以共享文件复制和缓存排除逻辑，却不应共享所有文档筛选决定。初始化专用 README 覆盖也不应替换源码包的项目 README。

## 在制品形成之前检查

将本地链接验证放在打包暂存目录，检查相对路径是否能在该目录中解析，既能发现源仓库中的缺失文件，也能发现筛选导致的遗漏。所有目标都应位于包根目录内，不能借本机包外文件让检查通过。

失败时不替换已有制品，始终清理临时目录。回归应同时证明“引用记录进入包”和“缺失链接拒绝打包且原包未改变”，而不只断言某个路径出现在 tar 清单。

## 检查的边界

轻量检查只验证本地文件目标，不承担完整 Markdown 渲染、标题锚点或外部站点可用性。代码块和内联示例应跳过，URL 编码路径与带空格的尖括号链接需要识别；边界和示例应由测试明确。

Markdown 格式门禁同样要限定为项目文档。虚拟环境或生成目录中的依赖 README 不属于仓库规则的治理对象，应排除这些目录，而不是关闭规则或改第三方文件。
