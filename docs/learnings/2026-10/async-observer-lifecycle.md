# 异步观察器：隔离错误，但保留取消

观察器用于记录执行过程。如果日志写入失败，任务本身仍应返回原结果；如果调用者取消任务，任务则必须停止。这两种异常需要不同边界。

Python 3.11 的 `asyncio.CancelledError` 继承 `BaseException`，而普通实现错误继承 `Exception`。观察器的安全调用只捕获 `Exception`，因此也不会吞掉 `KeyboardInterrupt` 和 `SystemExit`。日志只包含回调名与异常类别，避免异常消息暴露业务输入。

```python
try:
    await callback(snapshot)
except Exception as error:
    logger.warning("Hook failed: %s", type(error).__name__)
```

执行器使用两层 `finally`：迭代结束通知放在迭代层，运行清理放在运行层。模型超时、工具异常和任务取消都会经过这些清理点；取消不会伪造一个正常完成结果。清理回调仍是尽力执行，再次取消或进程崩溃不保证输出完整。

观察器还需要独立快照。复制列表外壳不足以保护嵌套工具实参；只读 dataclass 也不能自动冻结内部字典。每次回调复制精简上下文和工具调用，既不暴露 Registry 或消息列表，又使观察器修改参数时无法改变已经准备好的工具执行参数。

工具开始通知应放在查找与参数校验成功之后。找不到工具或参数不合法只是准备失败，不能计为实际执行。准备后的参数直接用于执行，避免校验两遍。实际成功走成功通知，已知失败或异常走错误通知，取消继续向上传播；不能根据结果文本是否包含 `Error` 决定状态。

自检：观察器抛出普通异常后答案是否一致？取消后是否仍更新了历史？非法参数是否错误地记录了执行开始？每个工具是否只产生一个结束通知？
