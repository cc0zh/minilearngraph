## 3. 当前 mini 的可复用能力

调用路径为 `CLI → AgentLoop → AgentRunner → Provider / ToolRegistry`。

| 接入点 | 现状 | 业务用途 |
| --- | --- | --- |
| `instructions` | Loop 构造时配置 | 教学风格、反馈规则、业务使用要求 |
| `context_provider` | 每轮调用，无参，同步或异步，返回文本或 None | 当前目标、节点、图谱版本、近期证据快照 |
| `ToolRegistry` | Pydantic 参数校验、明确工具错误、异步执行 | 节点查询、练习生成、作答评价及状态读取 |
| `AgentResult` | 返回回答、新增消息和停止原因 | 展示完成或失败状态 |
| `AgentHook` / Trace | 观察 Runner 生命周期 | 开发调试与耗时观察 |

现有对话历史只在内存；Loop 仅在 `completed` 时追加本轮历史。Trace 不承担持久化、业务事务或恢复。工具写入成功后，模型仍可能失败，因此业务事实不能依赖最终回答或内存历史是否更新来保存。

业务数据通过领域服务读取与写入，工具和 API 复用同一套服务。Runner 不读取数据库、不计算掌握状态，也不决定图谱是否发布。初期以服务工厂为学习会话配置上下文和工具闭包，避免共享可变的当前节点绑定。

## 4. 原 LearnGraph 的实际解决方式

本节完整转述实施相关的调研结果，读者不需要访问原代码。调查基于本次会话提供的本地副本；该副本无法解析有效 Git HEAD，因此没有可复现提交 SHA。以下是当时的静态实现事实，不是对产品效果的实测结论。

### 4.1 目标澄清与图谱

目标向导由专用 API 调用 `GoalService`，模型输出结构化问题，用户作答后确认 Goal。问题包含 `reason`、`graph_impact`、自定义/跳过选项与默认假设。前端保存完整回答和跳过假设。自然语言时间描述与结构化排期字段分开保存。

图谱节点类型为 `root/concept/practice/assessment`；关系为 `contains/prerequisite/related/contrast/application`。向导生成节点时同时生成文本 `teaching_strategy`，描述讲解方式、例子、误区与可验证掌握标准，供节点对话和命题使用。

流式生成按“根节点 → 主干 → 分支两层展开”进行，批次先保存再推送。根或主干生成失败可能回退为通用规则内容，分支失败可跳过。此行为提供可审核候选结果，但不保证内容完整性。

发布检查唯一根、最少节点数、边合法性、重复、自环、连通性、结构环和 `expected_revision`。Agent 另有目标工具与图谱提案路径；`GraphChangeSet` 保存变更及来源消息，支持确认、拒绝和撤销。创建提案确认后直接发布，向导则有独立发布步骤。

### 4.2 学习、证据与状态

节点选区由前端明确提供，后端为每轮注入节点身份、说明、教学策略和状态。普通学习对话与 Agent 工具执行均使用明确上下文。

练习支持单选、多选、判断、填空、简答。题目与标准先保存；客观题按规则判分，简答题优先模型按要点评价，失败可回退启发式评价。统一作答方法保存答案、覆盖/缺失要点、Evidence，并更新学习状态。证据记录提示和重试，区分独立回忆。系统判定的错答即使为 pending，也参与学习状态计算。

原项目同时存在两套状态：

- 节点成长星级：0～15，只增不减；首次明确围绕节点提问也可加星；配套复习间隔为 1、3、7、14、30、45、60、90 天。
- 学习状态投影：按证据置信度、难度和辅助程度加权评分，生成 unseen、learning、weak、familiar、mastered、needs_review。包含来源证据与算法版本。

图谱、能力图谱和路线推荐主要仍使用星级、复习与证据状态，未统一改用连续掌握分数。能力图谱页面将节点挂在“能力成长”根节点下展示，不能由 README 推断为独立的全局能力关系模型。

### 4.3 行动推荐

原项目服务端检查前置条件，再按重要性 30%、掌握缺口 24%、复习紧迫度 18%、证据缺口 14%、截止日期 10%、偏好 4% 排序。行动保存评分分解、阻塞条件、验收要求和排期事实。

当前重新规划立即启用新 Roadmap，旧路线被替代并保留版本。图谱审核与路线启用的确认边界不同。以上权重是源码规则，不代表经过学习效果验证，也不要求 mini 照搬。

### 4.4 原项目算法，展开供独立理解

以下公式是原项目事实，不能直接与第 5 节的 mini 建议混用。

练习证据的难度值为 easy=0.3、medium=0.5、hard=0.7。辅助程度：有提示时为 `min(0.9, 0.4 + 0.2 × (提示数 - 1))`；无提示但重试时为 0.25；首次无提示为 0。证据置信度：错答 0.35，首次无提示答对 0.9，其他答对 0.7。这里置信度是规则赋值，不是模型返回的自信程度。

学习状态投影选择有效、已接受的证据，加上系统判定的练习错答。对每条证据计算：

```text
weight = max(0.05, evidence.confidence)
         × (1 + max(0, evidence.difficulty))
         × (1 - clamp(evidence.assistance_level, 0, 0.9))
mastery_score = sum(clamp(evidence.score, 0, 1) × weight) / sum(weight)
confidence = min(1, sum(weight) / 5)
```

没有分数时，correct/passed/success 视为 1，其他结果视为 0；无证据时分数为 0、状态为 unseen。状态按顺序判断：

1. 无证据：unseen。
2. 有错误证据且分数低于 0.5：weak。
3. 分数至少 0.85 且置信度至少 0.7：mastered。
4. 分数至少 0.65：familiar。
5. 其余：learning。
6. familiar/mastered 距最近评价至少 14 天：改为 needs_review。

这是规则模型，未体现题目之间的独立性；重复刷同题可能增加证据总量。不能把公式计算值宣传为经过校准的能力概率。

原项目推荐使用另一套节点星级。前置满足条件是星级至少 1，证据状态不为 none/interest_only/conflicted，且复习状态不为 relearning。评分输入如下：

| 输入 | 计算 |
| --- | --- |
| 重要性 | `clamp(goal_weight, 1, 100) / 100 × clamp(node_weight, 1, 100) / 100` |
| 掌握缺口 | `1 - clamp(stars, 0, 15) / 15` |
| 复习紧迫度 | relearning=1、due=0.9、due_soon=0.6、fresh=0.1、unverified=0.5；其他=0.35 |
| 证据缺口 | robust=0、cross_time=0.1、multi=0.25、single=0.5、interest_only=0.8、none/conflicted=1；其他=0.75 |
| 期限紧迫度 | 无期限=0；已过期=1；剩余至多 1/7/14/30 天分别为 0.95/0.75/0.55/0.35；更远=0.15 |
| 偏好匹配 | 行动类型在用户偏好中为 1，否则为 0 |

```text
priority = clamp(round(100 × (
    0.30 × importance + 0.24 × mastery_gap
    + 0.18 × retrieval_urgency + 0.14 × evidence_gap
    + 0.10 × deadline_urgency + 0.04 × preference_match)), 0, 100)
```

根节点不生成行动；已完成且未到复习时间、或满星且证据充分的节点可排除。前置被阻塞的行动保留显示并说明原因。可执行项按分数、节点权重、创建时间、ID 稳定排序。practice/assessment 节点生成对应行动，到期或重新学习的概念生成 review，其他概念生成 learn。

排期缺省采用每天 60 分钟、每周 5 天、每次 30 分钟，并公开假设。每次时长不超过每日容量，按可用学习日装入任务；学习日索引从 1 开始，日历偏移为 `ceil((day_index - 1) × 7 / days_per_week)`。超出期限明确标记，不承诺实际学习一定按时完成。

## 5. mini 建议领域契约

### 5.1 对象与事实源

| 对象 | 首版需要保存的内容 | 规则 |
| --- | --- | --- |
| Goal | 原始需求、用途、预期产出、基础、约束、澄清回答、假设、确认状态 | 模型建议与用户确认值可辨别 |
| Graph | 所属目标、状态、修订号、发布时间 | 发布与修改检查用户所见版本 |
| Node / Edge | 名称、描述、类型、权重、教学策略、关系 | 服务端校验节点归属与结构 |
| Session / Message | 所属目标、节点选区快照、角色、工具配对、轮次状态 | 回答与业务写入有各自明确状态 |
| Exercise | 节点、题型、题目、选项、答案、评分要点、生成依据 | 标准在作答前固定，答题响应不泄露答案 |
| Attempt / Evaluation | 提交标识、答案、评价状态、分数、反馈、提示与重试 | 原始答案保留；评价失败不伪造结果 |
| Evidence | 学习者、节点、来源引用、结果、分数、辅助程度、有效性 | 可追溯到 Attempt 或实践产出 |
| Mastery | 学习者与节点、状态、依据、最近评估、规则版本 | 由有效证据推导，不由模型直接任意改写 |
| Action | 关联节点、类型、理由、前置阻塞、生成时依据 | 建议由用户选择，完成行动不自动代表掌握 |

目标图谱表示需要学习的结构；能力视图以同一节点上的评估状态开始，不另造全局概念合并系统。记录节点内容版本，内容变化时显式处理既有题目和证据的适用性，保留历史来源。

### 5.2 关键状态与写入规则

- 目标先澄清并确认，才生成候选图谱。目标状态与图谱状态分开定义，避免把“目标确认”当成“图谱发布”。
- 图谱经过审核及结构校验后发布；重要修改保留修订记录，版本冲突返回可恢复错误。
- 学习活动单独记录。仅提问、浏览或听完讲解，不直接作为能力掌握的充分证据。
- 作答先保存事实再完成评价；正确、部分正确、错误、待评价需要区分。部分正确的分数和缺失要点不能压缩成单一布尔值。
- 提示和重试降低证据强度，错误证据参与判断；阈值与复习规则在实施计划中给出固定版本及边界案例。
- 推荐先检查前置条件，再考虑目标权重、薄弱程度、复习需求和时间。给出理由与证据不足提示，用户可以自行选择节点。
- 使用稳定提交标识保护练习提交及评价写入；同一标识重试返回同一业务结果，冲突内容明确报错。
- Attempt、Evaluation、Evidence 与状态更新明确事务边界。投影失败保留答案并标记待处理，不返回虚假的全成功结果。
- 工具业务写入成功但模型回答失败时，页面仍能查询已保存事实。重试不能重复产生证据或增长状态。
- 学习对话持久化必须保存角色与工具调用配对。失败轮次可展示失败状态，不能直接混入下一次有效模型历史；不为此引入通用 Run 恢复平台。

### 5.3 建议状态转换与图谱规则

本节是可落地的起始设计，尚未实施；最终命名在计划中确定，但不应留下不同对象共用含糊状态的情况。

| 对象 | 状态转换 | 守卫条件或失败行为 |
| --- | --- | --- |
| Goal | draft → confirmed | 用户审阅目标、回答与假设；模型不能代替确认 |
| Graph | generating → candidate → published | 生成完整、用户审核、结构有效、版本匹配 |
| Graph 生成 | generating → generation_failed | 模型失败或输出非法；显示原因，保留已确认目标，允许重试 |
| Published Graph | 修订 r → r+1 | 用户明确确认变更；保存 before/after 与 actor，不静默改图 |
| Attempt | submitted → evaluating → evaluated | 答案先落库；成功评价后记录证据 |
| Attempt 评价 | evaluating → evaluation_failed → evaluating | 原答案和题目标准不变；显式重评复用提交标识 |
| Action | suggested → in_progress → completed/skipped | 用户选择；completed 不等同于节点 mastered |

候选图谱起始约束：恰好一个 root、至少一个非根节点；ID 唯一；边端点属于本图；无重复边、自环；每个非根节点有且只有一个 contains 父节点，所有节点从 root 可沿 contains 到达；contains 与 prerequisite 的联合有向图无环。其他关系不要求无环。这是 mini 建议的教学层级约束，比第 4 节原向导发布时的无向连通检查更明确。

删除候选节点需要同时处理关联边和子节点：默认拒绝遗留孤儿的删除，用户先移挂子节点或明确删除子树。正式图谱删除/改动需有修订记录；旧题目和证据保留来源，不物理清空。

每次内容修改要求 `expected_revision`，服务端在事务内用条件更新推进版本。同一版本的两个并发修改只能有一个成功，另一个返回 409 与当前修订号。发布同理。生成的模型草稿没有发布权限。

### 5.4 从目标到图谱的结构化示例

以下是完整字段示例，不是要求照抄的最终 API。ID 与版本由服务端分配；模型只能建议内容与临时 ref。时间使用带时区的 ISO 8601。

```json
{
  "goal": {
    "id": "g1",
    "status": "confirmed",
```

### 5.6 mini 评估与推荐的可执行起点

这是独立于原项目双状态的建议规则，不是已确认产品算法；实施计划可以替换，但需要同样明确输入、阈值、版本和测试。

建议证据选择当前学习者、节点内容版本及有效评价。先按 exercise_id 分组，同题只取最新有效作答，避免多次提交增加证据数量。其余证据保留在历史视图。medium 难度取 0.5；难度与辅助取值可沿用第 4.4 节，评价可靠性暂固定为规则判分 1、有效模型评价 0.8，不因答对或答错改变可靠性。

计算 `w = reliability × (1 + difficulty) × (1 - assistance)`，掌握分为加权 score 平均，证据充分度为 `min(1, sum(w) / 5)`。无可用证据标记 unassessed，内部 score=null；前端不把未评估显示成“能力为零”。状态顺序：

1. 无证据：unassessed。
2. 加权分低于 0.5：weak。
3. 分至少 0.85、充分度至少 0.7、至少 3 道不同题且至少 2 道首次无提示全对：mastered。
4. 分至少 0.65：familiar；其余 learning。
5. familiar/mastered 距最新有效评价至少 14 天：needs_review，保留原分数和依据。

时间转换在读取状态或显式刷新时处理，测试使用注入时钟。复习建议起点为 mastered 14 天、其他已评估状态 3 天；weak 可立即推荐补学。仅有参与记录不生成这些能力状态。

推荐规则起点：根节点排除；前置节点须为 familiar/mastered 且不处于 needs_review。未满足时展示 blocked_by，并优先推荐可学习的前置节点。满足条件的节点按 learn/practice/review/assessment 生成建议，weak 优先补学或练习，needs_review 推荐 review。用户仍可自主访问被阻塞节点，只是不把它排在推荐学习主线。

排序可保留原权重但替换输入：mastery_gap 使用 `1 - score`（无证据时取 1），evidence_gap 使用 `1 - 充分度`；复习紧迫度 weak=1、needs_review=0.9、unassessed=0.5、其他=0.1。重要性、期限、偏好按第 4.4 节计算。分数相同按权重、创建时间、ID 稳定排序。必须记录规则版本与输入快照，不能沿用原项目星级门槛。

首版可只提供排序后的行动列表，不建设完整 Roadmap 排期。时间缺失不虚构用户承诺；如采用默认时间盒，显示是假设。业务完成标记、模型“你掌握了”的回答和浏览次数不参与评估。

## 6. 应用边界与 Web 交互

建议新增 `mini_learngraph/learning/`，承接领域模型、业务用例与数据访问。API 和 Agent 工具调用同一组用例，模型调用通过现有 Provider 边界。目录拆分到实际实现需要的程度，不预建空插件层。

目标澄清、图谱生成和评估可采用专用结构化模型请求；教学对话复用现有 Runner。接手者需明确结构化输出的获取与验证方式：当前内核没有现成的原项目 `generate_json` 协议，不得直接假设可调用。

Web 至少包含三个入口：

1. 目标列表与创建：输入目标、回答关键问题、审阅目标与假设、继续已有目标。
2. 图谱审核：查看候选节点与关系、调整内容、查看结构错误、确认发布。
3. 学习工作台：图谱选区、节点对话、独立作答区域、评价与掌握依据、下一步建议。

API 最少覆盖目标澄清与确认、候选图谱生成与发布、图谱查询与修订、学习会话与消息、练习生成与提交、状态和建议读取。这里是用例清单；最终路由、Schema 与错误码在实施时确定。

首版单个会话顺序处理，页面明确展示等待与失败并允许合理重试。是否采用对话 token 流或图谱增量流在计划中决定；原项目流式体验可参考，但完整 SSE 重放、后台队列和跨进程 Agent 恢复不作为首版前置条件。

SQLite 保存业务事实与学习会话。CLI `/reset` 仍只重置对话，不清空学习资产。业务会话重建与模型历史装配在调用层处理，遵守 Runner 不持有历史的边界。

### 6.1 模型职责与结构化请求

| 任务 | 提供给模型的输入 | 接收的输出 | 不允许模型决定 |
| --- | --- | --- | --- |
| 澄清 | 原始目标、已知约束 | 标题、问题、影响与假设 | 用户已确认、真实时间安排 |
| 图谱草稿 | 已确认目标、回答、透明假设 | 节点 ref、描述、教学策略、边 | 发布、真实 ID、能力状态 |
| 教学 | 当前目标、明确选区、状态依据、历史 | 讲解与必要工具调用 | 静默改变正式图谱 |
| 命题 | 节点内容版本、教学策略、题型与难度 | 题目、标准、rubric、提示 | 用户已答对、已掌握 |
| 简答评价 | 已存题目、固定 rubric、用户答案 | 已覆盖/缺失要点 ID、反馈 | 新评分标准、数据库状态 |
| 推荐解释 | 服务端生成的行动、理由和阻塞依据 | 自然语言解释 | 绕过前置检查、更改评估事实 |

所有输出通过 Pydantic Schema 和领域校验。用户答案、节点内容和资料是数据，不是可提高权限的指令。模型不能通过这些内容注册工具或发布图谱。

当前 Provider 只有 `chat(messages, tools) → ModelResponse`。最小适配建议在业务层组装 system/user 请求，使用 `tools=[]` 要求纯 JSON；只接受正常 stop、非空文本和无工具调用的响应，严格解析整个 JSON 对象，再验证 Schema。不要从自由文本中猜取片段或默认模型已支持原项目的 `generate_json`。失败返回生成/评价错误并允许显式重试，不伪造通用成功内容。若以后增加供应商 JSON Schema 支持，在 Provider 适配层实现并单独测试。

教学继续走 Runner；若练习工具内部再调用命题模型，应使用对应超时预算，不能沿用默认 10 秒工具时限导致正常模型请求被误杀。首版也可由页面直接调用专用命题/评价 API。

### 6.2 最小 API 契约建议

路由名称是建议；其语义可直接用作接口验收，不依赖任何外部实现。

| 用例 | 输入 | 输出与异常 |
| --- | --- | --- |
| 创建澄清草稿 | prompt | Goal 草稿与问题；失败返回可重试生成错误 |
| 确认目标 | goal_id、用户审阅后的字段、回答与假设 | confirmed Goal |
| 生成候选图谱 | confirmed goal_id | candidate Graph 或 generation_failed；不自动发布 |
| 修改/发布图谱 | graph_id、expected_revision、修改或确认 | 新修订/发布结果；409 版本冲突，422 结构错误及节点引用 |
| 创建学习会话 | goal_id、published graph_id | session_id；不能绑定其他目标图谱 |
| 发送学习消息 | session_id、selected_node_ids、content、submission_id | 回答、stop_reason、业务效果摘要；选区先验证归属 |
| 生成练习 | node_id、node_version、题型 | public Exercise；答案与 rubric 私有保存 |
| 提交/重评 | exercise_id、submission_id、answer；重评另传 attempt_id | Attempt 状态、评价、证据引用；同键不同内容 409 |
| 读取状态与推荐 | goal_id、learner_id 由服务端确定 | 状态依据、action reasons、blocked_by、规则版本 |

错误响应至少含 `code/message/details/retryable`，不泄露密钥或完整模型请求。只在本机个人模式下可使用固定学习者身份，并默认绑定回环地址；多人/LAN/公网访问前需另定认证授权。学习者身份不由模型实参或客户端随意指定。

### 6.3 数据提交顺序和失败恢复

```text
目标：输入 → 模型生成问题 → 校验草稿 → 保存 → 用户确认 → 保存 confirmed
图谱：confirmed Goal → 生成 → 校验并保存 candidate → 审核 → 事务校验版本并发布
学习：校验会话/选区 → 保存本轮输入快照 → 调用 Loop/Runner → 保存回答或失败状态
作答：校验题目版本 → 按提交标识保存 Attempt → 释放事务 → 评价
      → 短事务保存 Evaluation/Evidence 并更新 Mastery → 返回可查询结果
推荐：读取同一份图谱与状态快照 → 检查前置 → 排序 → 返回理由
```

模型请求期间不持有 SQLite 写事务。评价完成前再次检查题目与节点版本；若已变化，历史作答仍保存，但不能更新当前版本掌握状态。多请求抢占同一提交时通过唯一约束及条件状态更新保证只有一个有效评价落库。

教学消息与写工具也需要服务端稳定业务操作标识：重试同一消息提交时复用已保存操作结果，不仅依靠可能改变的模型 tool call ID 去重。注册给该会话的闭包绑定学习者、目标和节点范围；模型提供的 ID 必须再次校验，不能扩大写入范围。

单会话互斥覆盖选区获取、执行和历史保存；重启后仅装配成功且工具配对完整的轮次。若存在执行中轮次，标记 interrupted，提示用户重新发起，不自动重放工具。页面显示“对话失败但练习/提交已保存”等业务结果，不能让最终自然语言成为唯一事实源。

## 7. 分阶段实施与验收

| 增量 | 交付 | 必须通过的验收 |
| --- | --- | --- |
| B1：目标与图谱 | Web 创建、澄清、目标确认、候选审核、发布、持久化 | 假设可见；结构非法和过期版本不能发布；重启后可读取 |
| B2：节点学习 | 工作台选区、学习对话、上下文绑定、会话保存 | 切换节点后使用新上下文；历史快照可解释；失败不污染模型历史 |
| B3：作答与证据 | 固定题目标准、提交、评价、证据与状态 | 错答与部分正确可解释；重复提交不重复记证据；模型失败答案不丢 |
| B4：下一步行动 | 前置检查、规则推荐、理由与继续学习 | 推荐说明依据；被阻塞节点有原因；重启后完整闭环可继续 |

贯穿样例：用户希望“学习 Python，最终能独立处理一份 CSV 数据”，补充基础与时间，确认路线，学习一个基础节点，完成练习，查看评价与状态，选择下一步。该样例验证知识学习流程；本阶段不承诺执行用户代码或验证真实 CSV 产物。

必需验证分层：

- 领域与持久化：状态转换、图谱结构、修订冲突、事务、重复提交与证据来源。
- Agent 集成：工具写入后回答失败、切换节点、多轮工具配对、恢复会话与上下文快照。
- API：输入校验、资源归属、错误语义、题目答案隐藏及状态读取。
- Web：完成贯穿样例、刷新/重启继续、失败与重试、作答反馈可见。
- 仓库：相关静态检查、测试和 `npm run ci`；新增前端/API 检查接入现有流水线。
- 真实模型：单独记录模型与目标澄清、图谱生成、教学、评价结果；模型桩不计为真实效果验证。

以上是未来实施验收要求，本次文档交付未执行这些代码验收。

### 7.1 可直接转成测试的验收案例

下表依照第 5.6 节建议规则；若规则调整，计划中同步更新预期结果。

| 场景 | 操作或固定输入 | 预期 |
| --- | --- | --- |
| 透明假设 | 跳过基础问题 | 目标审阅页可见问题、跳过状态和采用假设 |
| 结构错误 | root contains A，A prerequisite root | 联合结构有环，不能发布，指出关联节点 |
| 修订冲突 | 两个编辑请求都基于 revision=1 | 一个推进到 2，另一个 409；不覆盖前者 |
| 切换选区 | 第一轮 loop，第二轮 csv | 第二轮当前快照为 csv；历史仍保留 loop 事实 |
| 无评估 | 仅讲解与提问 | 参与记录可见，Mastery 为 unassessed、score=null |
| 部分正确 | 三个评分点只覆盖两个 | score=2/3、result=partial，缺失点可见；不是全对 |
| 证据不足 | 一道规则判分 medium 全对、首次无提示 | weight=1.5、充分度=0.3，最多 familiar，不是 mastered |
| 充分证据 | 三道不同 medium 规则题首次无提示全对 | 分=1、充分度=0.9，mastered；再次提交同题不会多算第四道 |
| 复习风险 | 上述节点 14 天未评价 | needs_review，保存原分与证据，推荐 review |
| 错答 | 首个有效 medium 规则题得 0 | weak，进入证据与状态；不能过滤掉错误结果 |
| 幂等 | 同提交标识和答案发送两次 | 同一个 Attempt 和有效 Evidence；更换答案但复用标识为 409 |
| 评价失败 | 简答评价模型超时 | 答案仍在；无成功评价、无新增能力证据，可显式重评 |
| 模型回答失败 | 工具已保存练习，最终模型请求失败 | 练习可查询，重试不重复保存同一业务操作 |
| 内容变化 | 出题后节点内容升级为 version=2 | 旧作答保留在 version=1，不能增加 version=2 的掌握 |
| 推荐阻塞 | csv 前置 loop 为 weak | csv 建议含 blocked_by=loop，可执行推荐先补 loop |
| 继续学习 | 发布、对话、作答后重启服务 | 目标、图谱、会话、证据与状态可查；无需重新输入目标 |
